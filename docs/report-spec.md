# AI Report — Content Spec (REP-02)

Normative content spec for the per-video AI report generated by `POST /api/videos/:id/report`
(REP-05). REP-05 implements this document strictly; a behavior that is ambiguous here is a spec
gap to flag, not an implementation decision. No code in this ticket.

**Invariant (binding):** *every number in a rendered report is either a DB row value or a formula
from §1 — never model output.* The model contributes selection (indices) and words only.

## 1. Pre-computed metrics (computed in code, never by the LLM)

Inputs are DB rows after REP-03: `videos(duration_s, created_at)`,
`rallies(video_id, start_s, end_s, duration_s, peak_intensity)` ordered by `start_s ASC`,
`intensity_samples(video_id, t_s INT, intensity DOUBLE)` at 1 Hz, and the presence of a
`calibrations` row. Values are copied verbatim from rows — no re-derivation from video files.

Rounding: `round1(x) = Math.round(x * 10) / 10`. Applied once, at the context boundary (§2), to
every numeric leaving §1 into context. Hydrated values stored/§7-rendered are exact DB row values;
display formatting is §7's job.

### 1.1 Session level
| Metric | Formula (null handling pinned) |
|---|---|
| `rallyCount` | count of `rallies` rows for the video |
| `totalActiveTimeSec` | Σ `duration_s` over rallies (`0` when no rallies) |
| `activeTimePct` | `totalActiveTimeSec / videos.duration_s × 100`; field **omitted** if `duration_s` is NULL or ≤ 0 |
| `avgRallyDurSec` | `totalActiveTimeSec / rallyCount`; **omitted** when `rallyCount = 0` |
| `medianRallyDurSec` | sort durations asc; odd n → middle value; even n → mean of the two middle values; **omitted** when `rallyCount = 0` |
| `longestRally {durationS, startS}` | max by `duration_s`, tie → earliest `start_s`; **omitted** when `rallyCount = 0` |

### 1.2 Per rally
`rallyIndex` = 1-based position in `start_s ASC` order. Fields: `rallyIndex, startS, endS,
durationS, peakIntensityPxPerSec` — the last four copied verbatim from the row.

### 1.3 Highlight candidates
Top 5 rallies ordered by `peak_intensity` DESC → tie `duration_s` DESC → final tie
`rallyIndex` ASC (total order). Each candidate carries its **global** `rallyIndex`. This list is
the only set of rallies the model may cite; it does not need to see any other rally.

### 1.4 Notable intensity windows
```
b = floor(t_s / 60)                          # per sample
per bucket: mean = avg(intensity), max = max(intensity)   # both computed; context carries mean (§2)
peaks    = buckets sorted (mean DESC, fromS ASC), take first 3
troughs  = buckets NOT in peaks, sorted (mean ASC, fromS ASC), take first 3
windows  = peaks (index 1..3) ++ troughs (index 4..6)     # fewer than 6 only if < 6 buckets; a bucket never appears twice
window   = { index, fromS: b*60, toS: min((b+1)*60, videos.duration_s), kind: 'peak'|'trough', meanPxPerSec }
```
Only buckets with ≥ 1 sample exist. The last (partial) bucket's `toS` is the video end via
`duration_s`, not `max(t_s)+1`.

## 2. Context JSON shape (model input) — exact field names, no more, no less

```jsonc
{
  "video": {
    "durationSec": 20,            // round1(videos.duration_s); omitted if NULL/<= 0 (then activeTimePct also absent)
    "createdAt": "2026-10-31"     // DATE(videos.created_at), YYYY-MM-DD — for "sesión del …" prose
  },
  "hasCalibration": true,         // false → rendered report notes default court boundaries (§6/§7)
  "noRalliesDetected": false,     // rallyCount === 0
  "session": {                    // §1.1, round1 applied; avg/median/longest omitted at rallyCount = 0
    "rallyCount": 1,
    "totalActiveTimeSec": 19.6,
    "activeTimePct": 98,
    "avgRallyDurSec": 19.6,
    "medianRallyDurSec": 19.6,
    "longestRally": { "durationS": 19.6, "startS": 0.4 }
  },
  "highlightCandidates": [        // §1.3 — the only rallies citable by the model
    { "rallyIndex": 1, "startS": 0.4, "endS": 20, "durationS": 19.6, "peakIntensityPxPerSec": 938.9 }
  ],
  "intensityWindows": [           // §1.4 — the only windows citable by the model
    { "index": 1, "fromS": 0, "toS": 20, "kind": "peak", "meanPxPerSec": 163.2 }
  ]
}
```

Rules: field names pinned as above; every numeric second/pct/px-per-sec is `round1` of its source
value. The full rally list is **not** sent — candidates only (extra rows would add citation surface
without enabling any valid output).

Hard exclusions (normative, not stylistic):
- **No per-player / per-team data** anywhere in context. Known precision limitation of player
  filtering; documented decision and README talking point.
- **No user-controlled string enters the context.** Notably the video filename is NOT included —
  it would be a prompt-injection vector, and the UI displays the report beside the video name
  anyway. Every string value in context is either a fixed literal (`'peak'`/`'trough'`) or the DB
  date from `created_at`.

## 3. Output schema (structured JSON the model must return — indices + prose only, no numbers)

```json
{
  "summary": "<overall session picture, 1 paragraph>",
  "highlights": [ { "rallyIndex": 4, "reason": "<why this moment stands out>" } ],
  "intensityObservations": [ { "windowIndex": 2, "note": "<observation>" } ]
}
```

- `highlights` length **2–3**; fewer only if fewer candidates exist (§6). Every entry references a
  provided candidate by `rallyIndex`; duplicate `rallyIndex` = invalid.
- `intensityObservations` length **0–3**, each `windowIndex` unique, and every entry must match an
  `index` present in `intensityWindows`.
- `reason` / `note`: non-empty prose (whitespace-only counts as empty).
- The model emits no numeric values other than these indices. Inventing an index is the one hard
  failure mode validation exists to catch (§4).

## 4. Validation & hydration (server-side, post-model)

Each entry validated independently; invalid entries are **dropped and counted** — never fixed up,
never re-invented:

| Check | Fails when | Action |
|---|---|---|
| `rallyIndex` ∈ highlight candidates | otherwise | drop entry, count it |
| duplicate `rallyIndex` | already cited earlier | drop later entry, count it |
| `windowIndex` ∈ provided `intensityWindows[].index` (⊆ 1–6 by construction) | otherwise | drop entry, count it |
| duplicate `windowIndex` | already cited earlier | drop later entry, count it |
| `reason` / `note` non-empty after trim | empty/whitespace | drop entry, count it |
| `summary` present and non-empty string | missing/empty | whole response malformed → same path REP-05 uses for unparseable model JSON (no row stored) |

The response carries `validation: { dropped }`. If `dropped > 0`, `warnings[]` contains exactly one
server-generated entry: `"N invalid model reference(s) were removed"`.

Hydration — every kept entry is enriched **with the exact DB values** before anything is stored or
rendered, so no numeric value in a report ever passes through the model:
- highlight → `{ rallyIndex, startS, endS, durationS, peakIntensityPxPerSec, reason }` (first five
  verbatim from the `rallies` row; `reason` = model text)
- observation → `{ index, fromS, toS, kind, meanPxPerSec, note }` (window fields from §1.4)

Stored on the `reports` row:
```jsonc
// content (JSON column) — session kept for audit: exactly what the model saw
{
  "summary": "<model>",
  "highlights": [ { "rallyIndex": 1, "startS": 0.4, "endS": 20, "durationS": 19.6, "peakIntensityPxPerSec": 938.92, "reason": "<model>" } ],
  "intensityObservations": [ { "index": 1, "fromS": 0, "toS": 20, "kind": "peak", "meanPxPerSec": 163.2, "note": "<model>" } ],
  "session": <§1.1 session object as sent in context>
}
// rendered (MEDIUMTEXT) — the §7 text
```

**The summary is a documented trust boundary.** Prose cannot be fully number-audited without brittle
NLP (out of scope). Mitigations pinned here: the prompt steers the summary toward qualitative
references ("el punto más largo", "hacia el minuto 12") and allows concrete times only from the
notable windows; all hard numbers live in the validated structured sections. State this trade-off
explicitly — it's a README talking point, not an apology.

## 5. Audience & language (defaults `language=es`, `audience=coach`; invalid → 400)

| Param | Values | Effect |
|---|---|---|
| `language` | `es` (default), `en` | Output prose language + §7 section headings |
| `audience` | `coach` (default): tactical/technical framing with actionable observations. `player`: simpler, motivational wording. | Wording only |

**Same underlying numbers for both audiences** — no per-audience metric differences. Reports are
cached per `(video_id, language, audience)` (REP-03 schema).

## 6. Empty / incomplete data rules

| Situation | Behavior |
|---|---|
| `rallyCount = 0` | Report still generated: prompt instructs `highlights: []`; summary states no rallies were detected; intensity observations from samples when present (any highlight entry would fail §4 anyway) |
| No `intensity_samples` rows | `intensityWindows: []`; observations forced to `[]` by validation |
| `hasCalibration = false` (default calibration) | Context flag set (§2) **and** the rendered report notes analysis ran on default court boundaries (fixed footer line, §7) |
| Video's analyze job not `done` yet | Endpoint returns 409 with a clear message — no model call (route level) |

## 7. Rendered text

Server renders validated + hydrated JSON into exactly three sections; headings localized by
`language`: es "Resumen general" / "Momentos destacados" / "Intensidad a lo largo del video";
en "Overall summary" / "Highlighted moments" / "Intensity over time". Both structured JSON and this
text are stored in the `reports` row (REP-03); the UI (REP-06) displays the rendered text.

Formatting rules: all times/durations as `m:ss` — `fmt(s) = floor(s/60) + ":" + pad2(floor(s % 60))`
— computed from exact hydrated values; px/s and pct shown with 1 decimal (matching context).

```
Resumen general
<summary>

Momentos destacados
• Rally #4 · 1:23–1:46 (duración 0:23) · pico 950.6 px/s — <reason>

Intensidad a lo largo del video
• Ventana 2 (1:00–2:00, pico) · media 812.3 px/s — <note>
```

- Bullet labels ("Rally #N", "duración", "pico", "Ventana N", "media", kind "pico"/"valle") are
  localized per language; structure and value order fixed as above.
- Empty `highlights` → single localized line: es "Sin momentos que destacar." / en "No moments to
  highlight.". Same for empty observations ("Sin observaciones de intensidad." / "No intensity
  observations.").
- When `hasCalibration = false`, append after the three sections one fixed localized note that
  analysis ran on default court boundaries.

## 8. Prompt & model notes

- The prompt lives at `server/prompts/report-v1.js` and exports `buildPrompt({language, audience,
  context})`. Version string = filename suffix (`report-v1`), stored as `prompt_version` on every
  report row.
- The prompt must embed, in this order: (1) role + task; (2) language/audience instructions (§5);
  (3) the context JSON **verbatim** — `JSON.stringify(context)` of §2, no reformatting or field
  omission; (4) explicit anti-fabrication instruction, pinned wording: *"Only reference provided
  indices (rallyIndex from highlightCandidates, windowIndex from intensityWindows). Never invent or
  restate numeric values."*; (5) the output schema of §3 as the required response format.
- Generation is pinned to **temperature 0.3** for consistency across regenerations; structured JSON
  output is required (responseSchema). Model/provider specifics (Gemini free tier, model id
  `gemini-2.5-flash`) are REP-05's implementation detail and README material — this doc stays
  model-agnostic except where it constrains behavior (§3 shape, §8 temperature/structured output).
